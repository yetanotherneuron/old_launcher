# Developing Old Launcher

What the [README](README.md) leaves out: how the catalog is built, what the
app does to a client folder, how the code is laid out, and how to test it.

## The catalog

`index/wotlk.json` is the launcher's own catalog, generated by the `indexer`
tool and committed here:

```sh
GITHUB_TOKEN=$(gh auth token) cargo run --release -p indexer   # writes index/wotlk.json
```

The token only raises GitHub's API limits: a run makes about a hundred
calls, more than GitHub allows anonymously.

The indexer lists every upstream source, downloads every archive, and
records the addon folders each one installs (with their `.toc` title,
version and interface), when it was last updated, and the addon's own page
and history of changes at the source when it has them. Listings that install
the same folders are merged into one entry whose downloads are ordered
newest first (by version when the versions have the same shape, by date
otherwise), those made for 3.3.5a before the rest. Entries whose download
is dead, holds no addon or declares a later expansion's interface are left
out and reported, and links to dead or hijacked sites are dropped.

The sources, in order of preference (the first one listing an addon
describes it):

- [NoM0Re/WoW-3.3.5a-Addons](https://github.com/NoM0Re/WoW-3.3.5a-Addons),
  a curated collection, together with NoM0Re's own addon repositories.
- [locus313/WoW-3.3.5a-Addons](https://github.com/locus313/WoW-3.3.5a-Addons),
  a curated collection of backports.
- Backport maintainers on GitHub (ElvUI-WotLK, bkader, Bunny67, Zidras,
  s0h2x, KhalGH, Sattva-108, Xurkon): their own repositories that declare
  the 3.3.5a interface.
- [Rising Gods](https://addons.rising-gods.de/addons), a server's collection
  (descriptions in German).

An addon's update date is the newest file date inside its archive, which for
a repository snapshot is its last commit. locus313's zips are rebuilt daily,
so for those it is the last commit touching the addon's folder.

The app fetches the published catalog, `index/wotlk.json` as committed on
`main`, which a weekly CI schedule regenerates, and keeps the last copy
fetched in its cache directory, so the catalog shows instantly and offline
from the second run on. A refresh asks the repository whether the catalog
changed before downloading it.
`OLD_LAUNCHER_INDEX=<url or path>` at run time points the app at any other
catalog, such as a local `index/wotlk.json` while working on the indexer.

Sources live in `indexer/src/source/`, one module each, as types
implementing the `Source` trait (`info` describes it for the catalog, `list`
returns its listings). Adding one means writing that module and adding it to
the ordered list in `indexer/src/main.rs`; a GitHub maintainer is one more
name in `github::MAINTAINERS`.

The word "catalog" never appears in the app's own text: users see "the list
of addons", what is "available" and what is "up to date". It stays in the
code, the logs and here.

## How it works

There is no database. Everything is read from the client folder itself:

- **Installed addons**: every folder in `Interface/AddOns` and its `.toc`.
- **Where an addon came from**: installing drops a small
  `.old_launcher.toml` marker (source, catalog entry, URL) into each folder
  it creates. The client ignores it. Folders without a marker show as
  installed manually, one card per folder.
- **Addons installed before the launcher**: after each scan, unmarked folders
  that exactly match a catalog entry (every folder it installs is present)
  get that entry's marker. Bundles are matched before entries shipping one of
  their folders alone. The marker names the download whose recorded `.toc`
  versions best match the installed ones, or the preferred download when
  none does.
- **Addon data**: `WTF/Account/<account>/SavedVariables/<Addon>.lua` and the
  per-character `…/<realm>/<character>/SavedVariables/<Addon>.lua`, plus
  their `.bak` copies.

Archives are extracted to a hidden staging folder inside `Interface/AddOns`.
The walk goes breadth-first until it finds a folder holding a `.toc`. That
folder moves into place under the name its `.toc` declares, and the walk does
not descend into it, since deeper `.toc` files belong to embedded libraries.
So only `Name/Name.toc` layouts ever reach `Interface/AddOns`, whatever the
archive looks like.

An update is offered when the catalog's `.toc` version of an installed
folder is newer than the one on disk, or differs from it without comparing.
Versions compare only when they have the same shape (`r736` and `r720`,
`1.2.3` and `1.3`, `1.19.5 (r240)` and `1.19.5 (r238)`); `r736` and `1.2`
do not. An installed version newer than the catalog's is said to be, and
offered a reinstall only.

The catalog's version of an entry is that of its first download, the newest
as the indexer orders them, unless the user picked a source on the card.
The pick is saved in the settings file (`sources`, by the entry's key: its
folders, lowercase, sorted and joined by `/`) and applied to every catalog
loaded: that source's download is the one installed and what updates are
measured against. Installing never falls back to another source, picked or
not: what the card says is what gets installed, and a failed download is
reported in the banner with the source named.

**Play** starts `Wow.exe` from the client folder on Windows. Elsewhere it
runs the client's command with `sh`, the way Steam runs launch options: the
environment variables are set and exported first, and `%command%` becomes
the quoted path to `Wow.exe` (`wine %command%` when there is no command).
`~` and `$HOME` expand as in a terminal.

The only file outside the clients lists the client folders, how each one
starts and the sources picked per addon:
`~/.config/old_launcher/config.toml` (the platform config directory
elsewhere), or `$OLD_LAUNCHER_CONFIG` when set. If it can't be read, the
launcher does nothing else until you choose: it shows why, where the file
is, and which client folders overwriting it would forget, and offers to
edit it (then read it again), quit, or overwrite it with new settings.

## Layout

- `core/`: data and filesystem logic, no GUI and no network (TOC parsing,
  client detection, archive extraction, install/uninstall/repair/clean,
  the catalog schema, adoption, launch commands, and the `library` the list
  is filtered from). Unit-tested against temporary directories.
- `indexer/`: the CLI that builds `index/wotlk.json` from the upstream
  sources.
- `src/`: the iced app. `lib.rs` is the shell, with one TEA cell per screen
  (`setup`, `clients`, and `addons` with its cards and confirmation
  dialogs). Screens are tested with `iced_test::simulator`.
- `docs/plans/`: work planned but not started.

Nothing outside tests may panic on purpose: the workspace denies `unwrap`,
`expect`, `panic!`, `unreachable!`, `todo!` and `unimplemented!` through
clippy (tests are exempt, see `clippy.toml`). Whatever goes wrong while the
app runs ends up in the error banner at the top, which lists every problem
until dismissed.

## Tests

```sh
cargo clippy --workspace --all-targets   # also enforces the no-panic rule
cargo test --workspace
# Installs real catalog entries into a client, then uninstalls them
# (entries whose folders the client already has are skipped):
OLD_LAUNCHER_TEST_CLIENT="/path/to/World of Warcraft 3.3.5a" \
    cargo test --lib addons -- --ignored
# Renders the README's screenshots from a demo client:
SCREENSHOT_CLIENT=/tmp/demo SCREENSHOT_OUT=/tmp/shots \
    cargo test --lib screenshots -- --ignored
```

The committed screenshots are rendered inside a container, so the demo
client sits at `/home/player/Games/World of Warcraft 3.3.5a` and the text
is drawn with iced's bundled font rather than the system's:

```sh
podman run --rm -v "$PWD:$PWD:ro" -v old_launcher-target:/target \
    -v ~/.cargo/registry:/usr/local/cargo/registry -v ~/.cargo/git:/usr/local/cargo/git \
    -v /tmp/shots:/out -w "$PWD" -e CARGO_TARGET_DIR=/target -e ICED_TEST_BACKEND=tiny-skia \
    -e "SCREENSHOT_CLIENT=/home/player/Games/World of Warcraft 3.3.5a" -e SCREENSHOT_OUT=/out \
    docker.io/library/rust:1.98.1 cargo test --locked --lib screenshots -- --ignored
```

The launcher says what it does on stderr; `RUST_LOG=old_launcher=debug` says more.
